# DnDGem 0.1.0-alpha.3 — Cross-Framework Alpha Recovery

**Status:** **PRE-PUBLISH READY** — versioned in repository; npm publication pending maintainer authorization.

**Brand:** DnDGem by DA62

**Release date:** _(set on publication)_

**Category:** Content-Aware Adaptive Layout Engine — Framework Expansion (recovery)

---

## Recovery reason

`0.1.0-alpha.2` was published, but the first bootstrap of `@dndgem/vue`, `@dndgem/angular`, and `@dndgem/svelte` used direct `npm publish` from package directories. That bypassed pnpm workspace protocol rewriting, leaving published dependency metadata as `@dndgem/core: workspace:*` and `@dndgem/dom: workspace:*`. External consumers fail with `EUNSUPPORTEDPROTOCOL`.

`0.1.0-alpha.3` republishes all six public packages lockstep through the repository-approved pnpm/OIDC path with correct resolved semver dependencies in tarball metadata. **No runtime API changes.**

`0.1.0-alpha.2` is **superseded** for external installs. Do not use Vue/Angular/Svelte `@alpha` or exact `0.1.0-alpha.2` installs from npm.

## What this Alpha includes

Same cross-framework surface as [0.1.0-alpha.2](./0.1.0-alpha.2.md):

| Area           | Capability                                                                                |
| -------------- | ----------------------------------------------------------------------------------------- |
| Vue            | `@dndgem/vue` adapter (`vue@^3.5` peer)                                                   |
| Angular        | `@dndgem/angular` adapter (`@angular/core@^20 \|\| ^21 \|\| ^22` peer)                    |
| Svelte         | `@dndgem/svelte` adapter (`svelte@^5` peer; client/server export boundary)                |
| Next.js        | Validated with `@dndgem/react` (App Router, `'use client'` integration root)              |
| Nuxt           | Validated with `@dndgem/vue`                                                              |
| SvelteKit      | Validated with `@dndgem/svelte` (SSR import/build shell safe; client session after mount) |
| Core/DOM/React | Version-aligned with adapters on the shared `@alpha` channel                              |

All six public packages share **`0.1.0-alpha.3`** via Changesets fixed group.

## Install

```bash
# React (pulls @dndgem/dom + @dndgem/core)
npm install @dndgem/react@alpha

# Vue
npm install @dndgem/vue@alpha

# Angular
npm install @dndgem/angular@alpha

# Svelte
npm install @dndgem/svelte@alpha

# Vanilla / DOM
npm install @dndgem/dom@alpha
npm install @dndgem/core@alpha
```

Official version: **`0.1.0-alpha.3`**. Always use dist-tag **`alpha`**.

Exact version installs also work: `@dndgem/*@0.1.0-alpha.3`.

### Meta-framework environments (not npm packages)

| Environment | Install adapter                    |
| ----------- | ---------------------------------- |
| Next.js     | `npm install @dndgem/react@alpha`  |
| Nuxt        | `npm install @dndgem/vue@alpha`    |
| SvelteKit   | `npm install @dndgem/svelte@alpha` |

There is no `@dndgem/next`, `@dndgem/nuxt`, or `@dndgem/sveltekit`.

### Dist-tags (expected after publication)

| Dist-tag | Expected                                                    |
| -------- | ----------------------------------------------------------- |
| `alpha`  | `0.1.0-alpha.3` (official Alpha channel)                    |

Do not treat bare `npm install @dndgem/*` / `latest` as the supported Alpha path.

## Upgrade from 0.1.0-alpha.2

- Reinstall all adapters with `@alpha` — six packages align on `0.1.0-alpha.3`.
- If you attempted `0.1.0-alpha.2` for Vue/Angular/Svelte and hit `EUNSUPPORTEDPROTOCOL`, switch to `@alpha` after this release.
- Core/DOM/React `0.1.0-alpha.2` tarballs were installable; alpha.3 is lockstep alignment with corrected framework bootstrap metadata.
