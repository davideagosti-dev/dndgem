## What this Alpha adds

Phase 3 Adaptive Auto-Layout on top of the existing Technical MVP / Public Alpha foundation:

| Area   | Capability                                                                                                                                    |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Core   | Public `createAutoLayoutProposal` (+ `AutoLayoutProposal`, `AutoLayoutProposalInput`, `PlacementOrigin`) composed with existing `solveLayout` |
| DOM    | Opt-in `createLayoutSession({ autoLayout: true })` with partial/absent Source Intent; `state.autoLayout.proposalUnplacedItemIds`              |
| React  | Matching `DnDGemProvider` `autoLayout` prop (default off)                                                                                     |
| Hybrid | Source Intent retained; generated placements for automatic items; previous layout is stability-only                                           |
| Drag   | Accepted drop promotes only the active item to Source Intent                                                                                  |

Auto-Layout is **opt-in** (default off). `proposalUnplacedItemIds` is proposal completeness metadata — distinct from solver VALID / DEGRADED / INVALID.

## Minimal Auto-Layout example (opt-in)

```ts
import { createLayoutSession } from '@dndgem/dom';

const session = createLayoutSession({
  container,
  items,
  autoLayout: true,
  desiredPlacements: {
    revenue: { x: 12, y: 12, width: 180, height: 88 },
    // other items may be omitted — Auto-Layout proposes them
  },
});

// Proposal completeness (not solver validity):
session.getState()?.autoLayout?.proposalUnplacedItemIds;
```

React:

```tsx
<DnDGemProvider autoLayout items={items} desiredPlacements={{ revenue: … }}>
  …
</DnDGemProvider>
```

- Auto-Layout remains **opt-in** (not default-on)

- Keyboard drag deferred
- Screen-reader drag UX deferred
