# DnDGem 0.1.0-alpha.0 — Public Alpha release notes

**Status:** Draft for DND-2.5 Stage A. Finalized after successful npm publication under dist-tag `alpha`.

**Brand:** DnDGem by FinGem-AI  
**Category:** Content-Aware Adaptive Layout Engine  
**Tagline:** Drag. Resize. Adapt. Without breaking your content.

```text
GEOMETRICALLY FITS  ≠  CONTENT REMAINS USEFUL
```

This is an **early public developer release** (`0.x` prerelease). The Alpha API is intentional but **not** SemVer 1.0. Breaking changes remain possible during 0.x and will be changelogged.

---

## What this Alpha contains

| Package         | Role                                                                |
| --------------- | ------------------------------------------------------------------- |
| `@dndgem/core`  | Domain, constraints, validity, scoring, deterministic `solveLayout` |
| `@dndgem/dom`   | Measurement, resize, pointer drag, Vanilla `createLayoutSession`    |
| `@dndgem/react` | Thin React adapter (`DnDGemProvider` + hooks)                       |

Core capabilities:

- Content-aware constraints (hard geometry vs usefulness)
- VALID / DEGRADED / INVALID evaluation with scoring
- Deterministic adaptive solve / reflow
- Pointer drag → `LayoutIntent` proposals (Core remains authoritative)
- Responsive resize observation
- React and Vanilla integration paths

## Install (after publication)

```bash
# React apps (pulls @dndgem/dom + @dndgem/core)
npm install @dndgem/react@alpha

# Vanilla / DOM apps
npm install @dndgem/dom@alpha
```

Dist-tag: **`alpha`** (not `latest`).

Until packages appear on the registry, consume from this repository workspace or packed tarballs (`pnpm test:pack`).

## Performance context

Historical Technical MVP Core `solveLayout` medians on documented hardware were approximately **0.038–0.279 ms** for dashboard-scale scenes (up to ~40 items). These are **measurements under stated context**, not an SLA. See [Performance](../guides/performance.md).

---

## Known limitations (prominent)

- No Auto-Layout yet (Phase 3)
- No AI (Phase 4, after Auto-Layout)
- No Flutter / Vue / Angular / Svelte adapters
- Keyboard drag deferred
- Screen-reader drag announcements deferred
- Mobile / touch not validated
- Full SSR / hydration not validated (`DnDGemProvider` is client-mount only; module import is safe without `window`)
- Large-N behavior not established
- Absolute-positioning rendering model
- Repository may remain **PRIVATE** during first npm Alpha (GitHub links in package metadata may be inaccessible to outsiders)

Full list: [Limitations](../guides/limitations.md).

## Explicitly NOT implemented

Auto-Layout · AI · Flutter · other JS framework adapters · animation system · persistence helpers · nested layouts · commercial billing · cloud backend · telemetry · custom native DnD engine.
